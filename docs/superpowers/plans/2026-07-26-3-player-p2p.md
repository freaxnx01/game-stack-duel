# 3-Player P2P Mode Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add an optional 3-player P2P mode to Stack Duel (`index.html`) without changing existing 2-player hotseat or 2-player P2P behavior.

**Architecture:** Host-relay star topology — the host holds one `NetLink` per guest (array `this.nets`, length `playerCount - 1`) and is the sole simulation/targeting authority, as it already is in 2-player P2P. Connection codes are exchanged sequentially, one guest at a time, reusing the existing host/join screens. The 2-player and 3-player paths share the same array-driven state (`state.players[]`, `state.wins[]`) and the same "last surviving player wins the round" rule, which is a strict generalization of today's 2-player logic.

**Tech Stack:** Single-file `dc` component (`index.html`), no build step, no test framework — manual QA only (matches existing repo convention).

## Global Constraints

- Additive only: 2-player hotseat and 2-player P2P must behave exactly as before. Every task that touches shared logic ends with a 2-player regression check.
- No build step, no new dependencies — this is a static buildless site.
- Follow existing code style: `dc` template syntax (`{{ }}`, `sc-if`, `sc-for`), 2-space indent, no semicolons-only style changes.
- Manual test gate only (per repo convention) — no automated test suite exists or should be added.
- Version/changelog: bump `version.js` and add a `CHANGELOG.md` entry as the final task, per this repo's existing versioning convention.
